<Warning>
  This page applies only to self-bundled `@layerswap/widget` integrations. The recommended loader packages construct providers internally; see [Wallets](/widget/wallets).
</Warning>

The self-bundled Widget receives a `walletProviders` array through `LayerswapProvider`. Each provider owns a wallet family's connection state and its balance, gas, signing, and transfer implementations.

## Choose an approach

| Approach | Loading | Use when |
|---|---|---|
| `getDefaultProviders()` | EVM eager; other configured families lazy | You want the standard wallet set |
| Lazy descriptors | Only selected SDKs load, when needed | You want a standard subset with a smaller initial bundle |
| Individual eager factories | SDK enters the initial application bundle | You need chain-specific provider overrides |
| Custom connection store | Controlled by your application | A third-party SDK owns wallet UX and state |

## Build the provider array once

Provider factories receive the loaded network settings from `LayerswapProvider`; you do not need to fetch settings or derive chains before creating them.

```tsx
import { LayerswapProvider, Swap } from '@layerswap/widget';
import { createEVMProvider } from '@layerswap/wallet-evm';
import { createStarknetProvider } from '@layerswap/wallet-starknet';
import '@layerswap/widget/index.css';

const walletConnectConfigs = {
  projectId: 'YOUR_REOWN_PROJECT_ID',
  name: 'Your App',
  description: 'Your app description',
  url: 'https://yourapp.com',
  icons: ['https://yourapp.com/icon.png'],
};

const walletProviders = [
  createEVMProvider({ walletConnectConfigs }),
  createStarknetProvider(),
];

export function Widget() {
  return (
    <LayerswapProvider
      config={{ apiKey: 'YOUR_API_KEY', version: 'mainnet' }}
      walletProviders={walletProviders}
    >
      <Swap />
    </LayerswapProvider>
  );
}
```

Keep the array stable. Define it at module scope when its inputs are static, or memoize it when credentials or host-owned adapters can change. Rebuilding providers during render can reset provider-specific state and repeat initialization work.

Provider order does not change route availability. It changes which wallet families the connection UI can use.

## Reuse host wallet state

- If the host already has a wagmi `Config`, pass it to `createEVMProvider({ wagmiConfig })`. See [Sharing your wagmi config](/widget/wagmi-config) for the chain-merging and lifecycle behavior.
- If a third-party SDK does not expose wagmi, implement the current external-store contract in [Custom wallet management](/widget/advanced/custom-wallet-management).
