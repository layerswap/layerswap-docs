---
title: "Add deposits to your wallet"
description: "Let users fund a fixed address from any supported network or exchange with the Deposit Widget."
---

Your user holds funds somewhere else — in a wallet, on an exchange, or in another supported application — and needs them at an address your product already knows. The Deposit Widget fixes that receiving destination and lets the user choose an available way to fund it.

## Make sure this is the right Widget

Choose this integration when all of the following are true:

- your app can provide the destination network, allowed tokens, and recipient address before rendering;
- the user's main decision is **how to fund**, not where the assets should arrive;
- you want a single embedded component to handle the method picker, quote, transfer instructions, and progress; and
- you want the flow inline in your UI or behind a button that opens a dialog.

If users should choose the destination, start with the [Swap Widget](/widget/quickstart). If you need complete control over the screens and funding logic, use the [API](/api/quickstart).

## 1. Install and render

```bash
npm install @layerswap/widget-react
```

```tsx
import { LayerswapDepositWidget } from '@layerswap/widget-react';

// Module scope — these props are compared by identity;
// recreating them each render causes needless re-renders.
const config = { apiKey: 'YOUR_API_KEY', version: 'mainnet' };
const destination = { network: 'ARBITRUM_MAINNET', tokens: ['USDC', 'ETH'] };

export function DepositPage({ userAddress }: { userAddress: string }) {
  return (
    <LayerswapDepositWidget
      config={config}
      destination={destination}
      destinationAddress={userAddress}
      fallback={<div>Loading deposit…</div>}
      onError={(e) => console.error(e)}
    />
  );
}
```

`destination` (canonical network id + token symbols, case-insensitive) and `destinationAddress` are required — the widget never asks your user for an address. Only one widget (of either kind) can be live per page; a second instance renders an alert instead.

## 2. Choose the funding methods you offer

```tsx
<LayerswapDepositWidget
  // ...
  methods={['wallet', 'deposit_address']}
/>
```

Omit `methods` to offer everything: `wallet` (user connects and sends), `deposit_address` (user transfers from anywhere—exchanges included—without a source wallet connection), `hyperliquid`, and `polymarket`.

`deposit_address` is the method to keep if your users can't connect a wallet at all.

## 3. Detect completion

Wire callbacks — same event system as the Swap Widget:

```tsx
const callbacks = {
  onSwapCreate: (swap) => trackPending(swap),
  onSwapComplete: (swap) => creditUserBalance(swap),
  onError: (err) => report(err),
};
```

Pass `callbacks` as a module-scope or memoized object. For server-side confirmation, do not trust the client event alone—verify with `GET /swaps/{id}` or a [webhook](/api/webhooks) before crediting anything. See [Swap lifecycle & statuses](/concepts/swap-lifecycle).

## 4. Test, then launch

Use your **testnet key** with `version: 'testnet'`; the key selects testnet routes and the Widget value must match. Before production, set the Widget CSP in [Widget delivery and security](/widget/delivery-and-security) and handle the load-failure path in [Troubleshooting](/widget/troubleshooting).

## Variations

- Amount seeding: `defaultAmountUsd` (default `$1`, `0` disables).
- Button mode instead of inline: `mode="button"` with `buttonLabel`.
- Show the fixed address to the user: `showDestinationAddress`.
- Not React? The JavaScript package mounts the same deposit flow.

Before launch, complete the [Production checklist](/resources/production-checklist).
